# Lifly v0.3.x Cloud Sync MVP 修订号开发计划

## 1. 版本定位

v0.3.x 的目标是把 v0.2 已完成的本机 Local Data MVP 推进到 Cloud Sync MVP：同一用户在多端使用 Lifly 时，memo / task / expense 可以通过 PowerSync 与 Cloud API 形成最小同步闭环。

当前开发分支：

```text
feat/v0.3-cloud-sync-mvp
```

当前收口状态：

```text
0.3.1 Cloud API /sync/push：已完成
0.3.2 PowerSync credentials：已完成
0.3.3 Flutter uploadData：已完成
0.3.4 Settings 连接编排与诊断：已完成
0.3.5 sync smoke 脚本：已完成
0.3.6 release gate 与合并准备：核心检查与 live smoke 均已通过
```

收口文档：

```text
docs/development-plans/v0.3.6-cloud-sync-release-gate.md
```

稳定起点：

```text
v0.2.8
```

## 2. 版本目标

```text
Cloud API 提供同步写入 endpoint
PowerSync uploadData 能把本地 CRUD 上传到云端
memo / task / expense 的云端写入语义与本地语义对齐
用户身份和 token 能支撑 PowerSync credentials
同步失败有可诊断状态
Flutter settings 能展示同步状态
基础跨端场景可验证：A 端写入，B 端可见
```

## 3. v0.3 明确不做

```text
不做复杂冲突解决
不做端到端加密
不做团队协作
不做细粒度共享权限
不做完整生产账号体系
不做附件二进制同步
不做导入导出批量同步
不做 AI 写入链路扩展
不做 UI 大规模美化
```

v0.3 只解决“单用户多端基础同步可用”。

## 4. 修订号规划

### 0.3.0：Cloud Sync 边界冻结与 schema 对齐计划

原因：v0.3 会同时触碰 Flutter PowerSync、Cloud API、数据库模型和同步语义，必须先冻结边界，避免把账号体系、冲突解决和附件同步提前混入。

内容：

```text
建立 v0.3.x 开发计划文档
确认 v0.3 只做 Cloud Sync MVP
梳理 PowerSync schema 与 Cloud API 模型差异
列出 memo / task / expense 的同步字段清单
明确同步写入 endpoint 形态
明确最小身份/token 策略
```

验收：

```text
docs/development-plans/v0.3.0-cloud-sync-mvp.md 入仓
docs/development-plans/README.md 指向当前 v0.3 计划
当前分支为 feat/v0.3-cloud-sync-mvp
v0.3 不做范围已明确
```

建议提交：

```text
feat(sync): 规划v0.3.0云同步mvp
```

### 0.3.1：Cloud API 同步写入基础接口

原因：PowerSync uploadData 需要明确的云端写入目标；如果先写客户端 uploadData，会缺少服务端契约。

内容：

```text
新增同步写入 router/service 基础结构
定义 memo / task / expense upsert 与 soft delete payload
统一 user_id / source / revision / updated_at 处理
保留幂等写入入口
补充 FastAPI 单元或集成测试
```

验收：

```text
Cloud API 能接收本地 memo 写入 payload
Cloud API 能接收本地 task 写入 payload
Cloud API 能接收本地 expense 写入 payload
soft delete 不物理删除
重复提交不产生重复实体
API 测试通过
```

建议提交：

```text
feat(sync): 实现v0.3.1云端同步写入接口
```

### 0.3.2：PowerSync credentials 与最小身份接入

原因：PowerSync 连接需要 credentials。v0.3 不做完整生产账号体系，但必须有最小可测试身份和 token 流程。

内容：

```text
定义开发期用户身份策略
实现 PowerSync credentials endpoint 或等价 token 提供方式
Flutter 配置 PowerSync endpoint / token
settings 显示 credentials 与连接诊断
补充 token 失败和过期诊断
```

验收：

```text
Flutter 可以获取 PowerSync credentials
token 获取失败时 settings 可见
PowerSync endpoint 可配置
不引入完整生产登录 UI
```

建议提交：

```text
feat(sync): 接入v0.3.2最小同步身份凭据
```

原因：v0.2 本地写入已经进入 PowerSync，本轮要让本地 CRUD 能通过 uploadData 上传到 Cloud API。

```text
将 PowerSync CRUD batch 转成 Cloud API sync payload
处理 memo / task / expense create/update/delete
上传成功后 complete batch
上传失败保留 batch 并记录诊断
补充 uploadData 单元测试或可控集成测试
```

验收：

```text
本地 memo 创建后可触发上传
本地 task complete 后可触发上传
本地 expense 创建后可触发上传

```

建议提交：


### 0.3.4：Cloud -> Local 基础下行验证

原因：只上传不下行不能称为同步。需要确认云端数据可以被 PowerSync 下发并被 Flutter 页面读取。

内容：

```text
确认 PowerSync rules / backend schema 与 Flutter schema 对齐
准备可测试的 cloud seed 数据
验证 memo / task / expense 下行到本地表
Flutter 页面读取下行数据
补充下行 smoke 或手工验证脚本
```

验收：

```text
云端 memo 可在 Flutter 本地列表出现
云端 task 可在 Flutter 本地列表出现
云端 expense 可进入本地 summary
schema 不匹配时有明确诊断
```

建议提交：

```text

```

### 0.3.5：同步状态诊断与错误恢复

原因：同步失败是 v0.3 最容易影响用户信任的部分，必须在 settings 中可见并可复查。

内容：

```text

settings 展示连接状态 / 最后同步时间 / 最后错误
提供手动 reconnect / disconnect 入口
记录 uploadData 错误摘要
补充诊断 UI 测试
```

验收：

```text
断网时用户能看到同步失败状态
恢复网络后可手动重连
最后错误不导致页面崩溃
诊断信息不泄露敏感 token
```

建议提交：

```text
feat(settings): 增加v0.3.5同步状态诊断
```

## 6. v0.3 Definition of Done

```text
1. memo / task / expense 本地写入可以上传到云端
2. 云端 memo / task / expense 可以下行到本地
3. 单用户两端数据最终可见
4. soft delete 可以同步
5. 上传失败不丢本地数据
6. settings 有同步状态和错误诊断
7. Flutter 检查通过
8. API 检查通过
9. pnpm typecheck/test 通过
10. Local MCP smoke 不被破坏
11. 同步 smoke 通过
12. 不包含复杂冲突解决和生产级账号体系
```
