# Lifly v0.7.1 手机端导航与产品能力地基缺口规划

## 1. 版本定位

v0.7.1 是一次规划与范围冻结版本，不是 Flutter 页面美化版本，也不是后端接口实现版本。

本轮目标是把手机端产品设计中已经出现、但当前数据层还不能稳定支撑的能力先固化为长期架构边界，避免客户端为了追求页面效果写死字段、写假数据、写临时拼接逻辑。

```text
本轮平台重点：规划文档 / 长期产品地基 / API 契约边界
涉及平台：手机端 Flutter、Web/桌面端适配原则、服务端 API、同步 schema、repository 层
本轮不改：服务端业务代码、Flutter UI 代码、数据库 migration、同步实现
```

v0.7.1 之后再进入实现时，必须按以下顺序推进：

```text
先服务端/数据模型/read model
再 repository 与同步 schema
再 Flutter 页面消费真实接口
最后做视觉层级和交互美化
```

原因很明确：这些新页面不是单纯 UI 外壳，里面包含预算、提醒策略、AI 分类、混合最近内容流等产品能力。如果数据地基没有先定义，手机端页面会被迫散落大量硬编码和假逻辑，后续维护成本会很高。

## 2. 当前底座判断

当前 Lifly 已经具备以下核心底座：

```text
备忘 Memo
记账 Ledger
任务 Task
AI Capture parse / commit / undo
资产 Asset
导入导出 Import / Export
审计 Audit
撤销 Undo
同步 Schema / Push / Pull
Dashboard 轻量聚合
```

当前底座能够支持：

```text
备忘列表、详情、搜索、创建、编辑、删除
记账流水、分类、summary、微信/支付宝导入、导出
任务列表、今天、逾期、完成、due_at/remind_at/priority
AI 输入解析、候选动作确认、提交、撤销
首页轻量统计和最近交易
```

但手机端设计里已经出现了更高阶能力：

```text
今日关注
紧急提醒
预算进度
分类占比
消费洞察
AI 自动标签
AI 提醒策略
聊天式 AI 捕获
语音输入
附件参与 AI 解析
混合最近内容流
数据与设置摘要
```

这些能力不能仅靠 Flutter 改布局完成，必须补服务端 read model、数据模型、repository 和本地同步边界。

## 3. 统一原则：接口不能写死在客户端

### 3.1 客户端只消费契约，不推导产品规则

Flutter 客户端允许做展示格式化，但不应该在页面里长期写死以下逻辑：

```text
预算进度怎么算
什么叫紧急事项
分类颜色是什么
AI 是否已分类
任务提前几天提醒
哪类流水算异常消费
首页最近内容如何排序
哪些设置项需要提醒用户
```

这些规则应该由服务端 read model 或本地 core repository 输出结构化字段。

### 3.2 所有产品语义都要有 schema_version

新增聚合接口建议统一带：

```text
schema_version
generated_at
user_timezone
source_mode
```

用于后续移动端、桌面端、Web 和本地同步演进。

### 3.3 枚举要统一，不允许页面各自发明字符串

新增枚举需要在服务端 schema、客户端 entity、同步 schema 中保持一致。例如：

```text
attention_severity: critical / warning / info
activity_type: memo / task / ledger_transaction / import_batch / capture_session
classification_source: ai / user / rule / import
classification_status: pending / suggested / confirmed / rejected
warning_level: critical / warning / normal
strategy_status: suggested / confirmed / dismissed / expired
```

### 3.4 可以有兼容降级，但不能有假产品能力

短期允许：

```text
没有预算时显示“未设置预算”
没有 AI 分类时显示“待整理”
没有任务策略时只按 due_at/remind_at/priority 展示
没有混合流时只展示已有最近交易并标注数据来源
```

不允许：

```text
客户端假造预算金额
客户端写死分类占比
客户端根据字符串随意判定 AI 已分类
客户端写死提前几天提醒
客户端伪造消费环比洞察
```

## 4. 手机端导航规则

### 4.1 手机端主导航冻结为 5 个入口

手机端底部导航应收敛为：

```text
首页 / 备忘 / AI / 记账 / 任务
```

其中：

```text
AI 是居中主按钮
搜索不再占底部一级入口
设置不再占底部一级入口
```

### 4.2 搜索入口降级

搜索进入方式：

```text
首页顶部全局搜索入口
备忘页内搜索 / 筛选
记账页内搜索 / 筛选
任务页内搜索 / 筛选
必要时桌面端保留侧边导航搜索入口
```

搜索仍然是核心能力，但在手机端不占一级导航。

### 4.3 设置入口降级

设置进入方式：

```text
首页右上角设置入口
首页数据/同步/导入摘要卡片中的诊断入口
桌面/Web 侧边栏可保留设置入口
```

设置页定位从“底部主功能”调整为“系统管理与诊断入口”。

### 4.4 多端适配原则

手机端、Web、桌面端不要求原模原样。

```text
手机端：5 底部导航 + AI 居中主按钮 + 高密度卡片流
Web/桌面端：可以使用侧边导航或 NavigationRail，保留更多入口
平板/宽屏：允许首页卡片双列、详情页左右分栏
```

同一业务能力使用同一 repository 和同一 API 契约，多端只改变布局和信息密度。

## 5. 首页 Home Overview read model

### 5.1 为什么需要新接口

当前 `/api/v1/dashboard` 更像工程统计接口，当前主要返回：

```text
memo_total
task_todo
task_total
month_expense
month_income
daily_trend
recent_transactions
```

这不足以支撑“今日关注页”。首页应该是用户打开 Lifly 后第一眼看到的注意力分发中心，而不是多个功能页的简单统计拼盘。

建议新增：

```text
GET /api/v1/home/overview
```

`/dashboard` 可以保留为轻量统计或兼容接口，新的首页产品形态应该走 `/home/overview`。

### 5.2 最小返回结构草案

```text
HomeOverview
  schema_version
  generated_at
  user_timezone
  attention_items[]
  today_metrics
  finance_overview
  finance_insights[]
  recent_activity[]
  sync_summary
  import_summary
  settings_summary
```

### 5.3 attention_items

用于首页顶部“今日关注 / 紧急提醒”。

```text
AttentionItem
  id
  source_type: task / ledger / memo / import / sync / ai_capture / system
  source_id
  severity: critical / warning / info
  title
  subtitle
  reason
  due_at
  action_type
  action_payload
```

排序规则由服务端负责，客户端只按返回顺序渲染。

最小来源：

```text
逾期任务
今天截止任务
高优先级任务
待确认 AI 分类
导入失败或待提交批次
预算超阈值
同步异常
```

### 5.4 today_metrics

用于首页概览数字。

```text
TodayMetrics
  memo_created_today
  task_due_today
  task_overdue
  task_done_today
  capture_pending_count
  ledger_expense_today
```

### 5.5 finance_overview

用于预算进度和本月收支。

```text
FinanceOverview
  period_key
  currency
  income_total
  expense_total
  budget_total
  budget_used_ratio
  budget_remaining
  category_breakdown[]
```

没有预算时：

```text
budget_total = null
budget_used_ratio = null
budget_remaining = null
budget_state = not_configured
```

### 5.6 finance_insights

用于消费洞察和异常提醒。

```text
FinanceInsight
  id
  insight_type: month_over_month / category_spike / budget_warning / unusual_transaction
  severity: warning / info
  title
  description
  metric
  comparison
  action_type
```

### 5.7 recent_activity

首页最近内容应该是混合流，不是只展示最近交易。

```text
RecentActivityItem
  id
  activity_type: memo / task / ledger_transaction / import_batch / capture_session
  source_id
  occurred_at
  title
  subtitle
  preview
  icon
  color_token
  action_type
```

排序规则：

```text
优先 occurred_at / updated_at
同一时间按 attention severity 加权
最多返回 10-20 条
```

### 5.8 sync/import/settings summary

用于首页底部的数据状态和系统入口摘要。

```text
SyncSummary
  status: ok / pending / error / offline
  pending_count
  last_synced_at
  message

ImportSummary
  latest_batch_id
  latest_status
  pending_batch_count
  failed_batch_count
  message

SettingsSummary
  data_mode
  api_status
  local_core_status
  needs_attention
  message
```

## 6. 备忘 AI 自动分类最小模型

### 6.1 当前问题

当前 `Memo.tags` 是 `List<String>`，能支撑标签展示，但不能支撑长期产品能力：

```text
AI 自动分类
分类置信度
AI 待分类 / AI 已分类
用户确认 / 拒绝分类
标签颜色、图标、排序
标签统计
按标签筛选 API
```

### 6.2 最小数据模型

建议新增结构化分类记录：

```text
memo_classifications
  id
  user_id
  memo_id
  label
  label_type: tag / type / topic / intent
  source: ai / user / rule / import
  confidence
  status: suggested / confirmed / rejected
  model_name
  created_at
  confirmed_at
```

同时新增标签元数据：

```text
tag_metadata
  id
  user_id
  name
  kind: memo / ledger / task / global
  color_token
  icon_token
  sort_order
  status
  created_at
  updated_at
```

### 6.3 API 草案

```text
GET /api/v1/memos?tag=&classification_status=&type=&limit=&cursor=
GET /api/v1/memos/{memo_id}/classifications
POST /api/v1/memos/{memo_id}/classifications/confirm
POST /api/v1/memos/{memo_id}/classifications/reject

```

### 6.4 UI 消费边界

Flutter 可以展示：

```text
[清单] [生活] [AI 已分类]
[读书] [知识] [AI 建议]
[待整理]
```

但这些状态应来自接口字段，不应由客户端根据 tag 文本猜测。

短期兼容：

```text
tags 仍可保留为 memo 的轻量冗余字段
memo_classifications 作为结构化分类事实
tag_metadata 负责颜色/图标/排序
```

## 8. 任务预警策略最小模型

### 8.1 当前问题

当前任务已有：

```text
due_at
remind_at
priority
task_status
Reminder
```

这些字段能支撑普通提醒，但不能支撑图里的：

```text
AI 建议提前准备
提前多天提醒
提醒策略已生成
紧急 / 预警 / 今天要做 分组
```

### 8.2 最小数据模型

建议新增任务提醒策略表：

```text
task_reminder_strategies
  id
  user_id
  task_id
  warning_level: critical / warning / normal
  warning_reason
  preparation_window_days
  suggested_start_at
  ai_suggested_remind_at
  confidence
  status: suggested / confirmed / dismissed / expired
  created_by: ai / user / rule
  created_at
  confirmed_at
```

### 8.3 API 草案

```text
GET /api/v1/tasks?group=today|urgent|warning|all
GET /api/v1/tasks/{task_id}/reminder-strategy
POST /api/v1/tasks/{task_id}/reminder-strategy/confirm
POST /api/v1/tasks/{task_id}/reminder-strategy/dismiss
```

任务列表 read model 建议直接返回展示字段：

```text
TaskListItem
  id
  title
  description
  due_at
  remind_at
  priority
  task_status
  warning_level
  warning_reason
  strategy_status
  suggested_start_at
  ai_suggested_remind_at
```

### 8.4 与 Reminder 表关系

```text
Task.remind_at 是任务当前生效提醒时间
Reminder 是提醒派发队列/记录
TaskReminderStrategy 是 AI/规则生成的提醒建议与用户确认状态
```

策略不是派发本身。策略确认后，才写入或更新 `Task.remind_at` 和 `Reminder`。

## 9. AI Capture 极简聊天式输入边界

### 9.1 当前问题

当前 AI Capture 已具备：

```text
文本输入
解析候选动作
选择动作
提交
撤销
```

但体验更像调试页，不是聊天式捕获面板。

### 9.2 极简聊天式边界

短期不重写 AI 能力，只在现有 parse / commit / undo 上包一层会话模型：

```text
CaptureSession
  id
  user_id
  status: active / committed / cancelled
  created_at
  updated_at

CaptureTurn
  id
  session_id
  role: user / assistant / system
  input_text
  asset_ids[]
  parsed_actions[]
  created_at
```

### 9.3 API 草案

```text
POST /api/v1/capture/sessions
POST /api/v1/capture/sessions/{session_id}/turns
POST /api/v1/capture/sessions/{session_id}/commit
POST /api/v1/capture/sessions/{session_id}/undo
```

### 9.4 附件参与解析

附件不直接塞进文本字段，应使用资产引用：

```text
asset_ids[]
asset_context[]
```

服务端根据资产元数据、可解析文本、导入批次或 OCR/STT 结果参与 AI 解析。

### 9.5 语音输入边界

语音输入拆成两层：

```text
录音/上传音频 Asset
STT 转文本后进入 CaptureTurn
```

v0.7.1 只规划边界，不实现录音、不接入 STT、不实现移动端权限逻辑。
