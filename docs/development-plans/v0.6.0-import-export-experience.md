# Lifly v0.6.x Import / Export / Asset Experience 全量开发计划

## 1. 版本定位

v0.6.x 的目标是把 v0.5 已完成的服务端附件、微信/支付宝导入、提交、回滚和导出能力，补齐为 Flutter 客户端可实际使用的体验层。

v0.5 已经完成数据闭环，但主要入口仍偏 API / smoke。v0.6 不再优先扩服务端能力，而是围绕 Flutter 页面、状态展示、用户确认、错误恢复和导出入口做体验收口。

稳定起点：

```text
v0.5.7
```

当前计划分支：

```text
develop/v0.6.0
```

## 2. 平台范围

```text
主要平台：Flutter 客户端 apps/client_flutter
配套平台：服务端 services/api，仅在 UI 需要缺口时小范围补接口
暂不处理：小程序
```

## 3. 版本目标

```text
导入入口可从 Flutter 访问
微信 / 支付宝账单可上传并预览
错误行 / 忽略行 / 重复行可见
用户确认后才 commit
已导入批次可查看并 rollback
导出入口可生成并下载 / 保存结果
附件库体验从 memo detail 扩展到可管理
诊断信息让用户知道失败原因和下一步
```

## 4. v0.6 明确不做

```text
不做复杂 OCR
不做自动扫描本机文件
不做后台自动导入账单
不做复杂字段映射编辑器
不做商业级文件管理器
不做公开分享附件
不做端到端加密
不做移动端原生分享菜单深度适配
不做小程序端
```

## 5. 修订号规划

### 0.6.0：导入导出体验层范围冻结

原因：v0.6 会同时触达 Flutter 页面、服务端接口、文件选择、错误状态和用户确认，需要先冻结页面流和版本切片。

内容：

```text
确认 Flutter import/export/asset 体验范围
确认页面流：导入入口 -> 上传 -> 预览 -> 提交 -> 批次详情 -> 回滚
确认导出入口：类型选择 -> 生成 -> 保存/复制诊断
确认附件库入口和 memo 引用边界
确认 v0.6 不做项

```


## 6. Definition of Done

```text
1. Flutter 可选择微信 / 支付宝账单文件并上传预览
2. Flutter 可查看导入预览行和错误/忽略原因
3. Flutter 可确认提交导入批次
4. Flutter 可查看导入批次列表和批次详情
5. Flutter 可按批次 rollback
6. Flutter 可导出 ledger CSV / memo Markdown / all JSON
7. Flutter 可查看附件库基础列表和状态
8. 所有危险操作都有二次确认
9. Flutter analyze/test 通过
10. 服务端非 integration 回归通过
```
