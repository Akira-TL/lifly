# 26. Lifly v0.1 架构冻结说明

## 1. 状态

Lifly v0.1 架构在本文档范围内冻结。AI agent 可以在冻结范围内实现功能，但不得擅自改变技术栈、模块边界、同步策略、MCP 策略。如需变更，必须创建 ADR。

## 2. 产品范围冻结

v0.1 只做：

- 备忘录 / 日记 / 文档
- 记账
- 任务提醒
- 附件
- CSV 导入
- Cloud MCP
- Windows Local MCP
- 本地离线
- 云端同步
- 审计与回收站

v0.1 不做：

- 完整日历 UI
- 多用户/家庭账本
- Android 通知监听
- 飞书/Notion 双向同步
- 完整复式记账
- 端到端加密
- 社交功能
- 团队协作
- 复杂块编辑器

## 3. 技术栈冻结

- Client：Flutter，Windows + Android first
- Backend：FastAPI + PostgreSQL
- Sync：PowerSync
- MCP：TypeScript，Cloud MCP 使用 HTTP，Local MCP 使用 stdio
- Assets：对象存储，PostgreSQL 只保存 metadata
- Monorepo：pnpm workspace + uv + Flutter 独立工程

## 4. 数据边界冻结

附件二进制不进入 PostgreSQL，不走 PowerSync。数据库只保存 asset metadata。

所有创建、修改、删除、导入、导出、MCP 写操作必须写 audit_logs。

CSV 导入必须走：

```text
import_batch → import_rows → preview → commit → ledger_transactions
```

禁止直接导入正式账单表。

## 5. MCP 边界冻结

第一版 MCP 工具：

```text
capture_parse
capture_commit
capture_undo
memo_create
memo_search
expense_create
expense_search
expense_summary
task_create
task_list
task_complete
asset_create_upload_url
asset_register_external_url
```

新增 MCP tool 必须先更新文档、schema 和测试。

## 6. 本地 MCP 冻结

Windows 可做 Local MCP。Android 不做 MCP Server。

Local MCP 必须复用 Cloud MCP 的 tool schema，走 Local Core Bridge，写本地 SQLite，并写 audit log。禁止直接绕过本地数据层写 SQLite。
