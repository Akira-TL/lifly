# UI 与信息架构

## 1. 设计原则

Lifly 的 UI 不是复杂工作台，而是快速记录和修正数据的工具。

原则：

- 快速输入优先；
- 今日视图优先；
- 搜索优先；
- 手动编辑要简单；
- AI 结果可预览、可撤销；
- 同步状态透明。

## 2. 一级导航

### 2.1 手机端一级导航

手机端底部导航固定为 5 个入口：

```text
首页 / 备忘 / AI / 记账 / 任务
```

入口职责：

```text
首页：今日关注、紧急事项、概览、最近混合活动、数据状态入口
备忘：高密度备忘列表、标签筛选、AI 分类状态、详情与编辑
AI：居中主按钮，进入聊天式 Capture 捕获体验
记账：流水、预算进度、分类占比、导入入口、消费洞察
任务：今天、紧急、预警、逾期、已完成
```

搜索不作为手机端底部一级入口，进入方式是：

```text
首页顶部全局搜索
备忘页内搜索和筛选
记账页内搜索和筛选
任务页内搜索和筛选
```

设置不作为手机端底部一级入口，进入方式是：

```text
首页右上角设置入口
首页同步/导入/数据状态摘要卡片
```

当前 Flutter `AppShell` 已完成基础入口收敛：手机端底部固定 5 个核心入口，AI 为居中主按钮；首页顶部已提供全局搜索和设置入口。首页同步/导入/数据状态摘要卡片入口仍随首页卡片改造继续补齐。

### 2.2 Web / 桌面端导航

Web 和桌面端不强制照搬手机端。宽屏形态可以使用侧边导航或 NavigationRail，并保留搜索、设置、导入导出、诊断等入口。当前 Flutter 宽屏基础形态先使用核心 5 入口 NavigationRail，更多管理入口后续随桌面/网页设计补齐。

原则是：

```text
多端共享数据契约和业务语义
多端不共享僵硬布局
手机端优先注意力和快速完成
桌面端优先信息密度和批量管理
```

## 3. 首页 / 今日关注页

首页不是简单 dashboard，而是用户打开 Lifly 后的注意力分发中心。

展示优先级：

```text
P0：紧急事项、逾期任务、今天截止任务、同步/导入异常
P0：今日关注 1-3 件事
P1：预算进度、本月支出、分类占比、消费洞察
P1：待 AI 整理、待确认分类、待确认 Capture
P1：最近混合活动，包含备忘、任务、流水、导入、AI Capture
P2：数据模式、同步状态、设置摘要
```

首页数据应来自 `home overview` read model，不在客户端页面临时拼接长期产品规则。正常联网时走云端 `/home/overview`；云端失败、断网或弱网时由 Local Core 基于本地 PowerSync 数据计算同构 read model 兜底。

## 4. AI Capture / 快速记录页

手机端 AI Capture 应降低学习成本，默认自动判断类型，不要求用户先选择“备忘 / 任务 / 记账”。核心输入形态：

```text
直接说或写，例如：中午食堂18，晚上8点提醒我改页面
```

最小操作：

- 文本输入；
- 长按 AI 语音入口，未接入 STT 前只能作为占位；
- 附件入口：图片 / 文件 / 流水；
- 继续整理 / 确认整理。

AI 解析后展示 action cards：

- 账单卡；
- 任务卡；
- 备忘卡。

用户可以修改某个 action、选择提交，并在 AI 完成设置后查看创建实体与撤销入口。页面已支持连续多轮、历史会话恢复、手机端历史面板、宽屏会话侧栏和附件选择；附件以 `asset_ids + asset_context` 展示真实解析状态。服务端可读取受限文本类附件，PDF/OCR/STT/外链抓取仍通过明确能力状态等待适配，不伪装成已完成。

## 9. 回收站

分为：

- AI 回收站；
- 普通回收站。

AI 回收站用于展示 AI 删除/隐藏的数据，用户可恢复或确认删除。
