# 22. UI 与信息架构

## 1. 设计原则

Lifly 的 UI 不是复杂工作台，而是快速记录和修正数据的工具。

原则：

- 快速输入优先；
- 今日视图优先；
- 搜索优先；
- 手动编辑要简单；
- AI 结果可预览、可撤销；
- 同步状态透明。

## 2. 一级导航

### 2.1 手机端一级导航

手机端底部导航固定为 5 个入口：

```text
首页 / 备忘 / AI / 记账 / 任务
```

入口职责：

```text
首页：今日关注、紧急事项、概览、最近混合活动、数据状态入口
备忘：高密度备忘列表、标签筛选、AI 分类状态、详情与编辑
AI：居中主按钮，进入聊天式 Capture 捕获体验
记账：流水、预算进度、分类占比、导入入口、消费洞察
任务：今天、紧急、预警、逾期、已完成
```

搜索不作为手机端底部一级入口，进入方式是：

```text
首页顶部全局搜索
备忘页内搜索和筛选
记账页内搜索和筛选
任务页内搜索和筛选
```

设置不作为手机端底部一级入口，进入方式是：

```text
首页右上角设置入口
首页同步/导入/数据状态摘要卡片
```

### 2.2 Web / 桌面端导航

Web 和桌面端不强制照搬手机端。宽屏形态可以使用侧边导航或 NavigationRail，并保留搜索、设置、导入导出、诊断等入口。

原则是：

```text
多端共享数据契约和业务语义
多端不共享僵硬布局
手机端优先注意力和快速完成
桌面端优先信息密度和批量管理
```

## 3. 首页 / 今日关注页

首页不是简单 dashboard，而是用户打开 Lifly 后的注意力分发中心。

展示优先级：

```text
P0：紧急事项、逾期任务、今天截止任务、同步/导入异常
P0：今日关注 1-3 件事
P1：预算进度、本月支出、分类占比、消费洞察
P1：待 AI 整理、待确认分类、待确认 Capture
P1：最近混合活动，包含备忘、任务、流水、导入、AI Capture
P2：数据模式、同步状态、设置摘要
```

首页数据应来自 `home overview` read model，不在客户端临时拼接长期产品规则。

## 4. AI Capture / 快速记录页

核心输入框：

```text
输入一句话，例如：中午食堂18，晚上8点提醒我改页面
```

按钮：

- AI 解析；
- 直接保存为备忘；
- 手动选择类型。

AI 解析后展示 action cards：

- 账单卡；
- 任务卡；
- 备忘卡。

用户可以删除某个 action，再提交。

- 全部；

- 日记；
- 摘录；
- 文档；
- 标签；
- 日期。

编辑页：

- Markdown；
- 附件；
- 预览；
- 标签；
- 类型选择。

## 6. 账单页

视图：

- 今日；
- 本周；
- 本月；
- 分类；
- 商户；
- 导入批次。

新建账单：

- 金额；
- 分类；
- 账户；
- 商户；
- 时间；
- 备注。

## 7. 任务页

视图：

- 今日；
- 待办；
- 已完成；
- 逾期；
- 全部。

任务卡：

- 标题；
- 提醒时间；
- 截止时间；
- 完成按钮；
- 来源标记，手动/AI。

## 8. 搜索页

统一搜索：

- 备忘录；
- 账单；
- 任务；
- 附件；
- 导入批次，后续。

## 9. 回收站

分为：

- AI 回收站；
- 普通回收站。

AI 回收站用于展示 AI 删除/隐藏的数据，用户可恢复或确认删除。
