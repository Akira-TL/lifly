# Lifly v0.7.x 客户端体验与移动端产品地基全量开发计划

## 1. 版本定位

v0.6 已经把导入导出体验层做成闭环：

```text
导入：选择文件 -> 上传预览 -> 完整预览 -> 提交 -> 批次追踪
导出：选择范围 -> 元数据预览 -> 下载导出流
门禁：Cloud API / Local Core 边界、测试、手动验收文档
```

v0.7.x 的定位从单纯“客户端 UI/交互体验统一”调整为“客户端体验统一 + 手机端核心导航 + 产品能力地基”。当前手机端设计已经包含今日关注、紧急提醒、预算进度、分类占比、AI 自动标签、AI 提醒策略、混合最近内容流等能力。如果先写 Flutter 页面，会出现假数据和客户端硬编码。

因此 v0.7.x 的推进原则调整为：

```text
先冻结功能地基和 API 契约
再补服务端 read model / 数据模型 / repository / 同步 schema
最后做 Flutter 手机端、Web、桌面端的真实 UI 消费
```

## 2. 平台范围

```text
主要平台：Flutter 客户端 apps/client_flutter
重点形态：手机端，其次兼顾 Web / Linux 桌面端
配套平台：服务端 services/api、同步 schema、repository 层
暂不处理：小程序
```

需要说清楚的是：

```text
手机端不是把 Web/桌面端压窄
Web/桌面端也不是照搬手机端
多端共享数据契约、repository 和业务语义，但布局可以不同
```

## 3. 总目标

```text
冻结手机端 5 底部导航规则：首页 / 备忘 / AI / 记账 / 任务
将 AI 作为手机端居中主按钮
将搜索降级为首页全局搜索和页面内搜索
将设置降级为首页入口和桌面/Web 管理入口
新增首页 home overview 聚合接口方向
补齐记账预算、分类占比、消费洞察的最小地基
补齐备忘 AI 自动分类、标签元数据、分类状态的最小地基
补齐任务预警策略和 AI 提醒建议的最小地基
把 AI Capture 从调试式页面规划为聊天式捕获体验
避免客户端写死预算、分类、预警、洞察、AI 状态等产品规则
最终再统一页面标题、卡片、列表、空状态、错误态和手动验收清单
```

## 4. v0.7 明确不做

```text
不做小程序端
不做多用户协作
不做复杂订阅计费
不做主题市场或复杂皮肤系统
不做没有真实数据地基的假预算图表
不做由 Flutter 页面临时拼接的首页今日关注
不做客户端写死的 AI 已分类状态
不做客户端写死的任务提醒策略
不做未接入 STT 的真实语音识别能力
```

## 5. 设计原则

```text
先产品地基，后视觉外壳
先 API/read model，后 Flutter 页面
先真实数据，后图表和强调色
先手机端核心路径，再适配 Web/桌面端
同一业务语义只能有一套契约，不允许多端各自发明字段
页面可以有兼容降级，但不能有假产品能力
```

## 7. 验收门槛

每个修订号至少满足：

```text
服务端 schema / repository / UI 边界清晰
客户端不写死产品规则
新增接口有测试
Flutter analyze 通过
相关 widget tests 通过
git diff --check 无输出
新增/修改文件行数符合限制
用户可手动打开对应 UI 路径验证
```

v0.7 最终发布前必须满足：

```text
bash scripts/check-client-flutter.sh 通过
服务端相关测试通过
手机端主要路径可用
Linux 桌面端主要路径可用
Web 主要路径可用，若当前环境没有 chrome，则记录为用户手动验收项
Cloud API / Local Core 边界提示正确
首页、备忘、AI、记账、任务、搜索、设置、导入导出页面无明显割裂
没有假预算、假分类占比、假消费洞察、假 AI 分类状态、假提醒策略
```
