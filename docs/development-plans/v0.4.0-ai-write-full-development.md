# Lifly v0.4.x AI Write 全量开发计划

## 1. 版本定位

v0.4.x 的目标是把 Lifly 从“本地优先 + 云同步可用”推进到“AI 写入成为完整一等入口”。

这里的“全量开发”不是指一次性做完所有 AI 想象空间，而是指 v0.4 版本族内必须形成完整产品闭环：协议、云端写入、本地写入、自然语言捕获、确认提交、撤销、审计、Flutter 入口、诊断、smoke 和 release gate 都要覆盖。

当前开发分支命名规则：

```text
develop/v0.4.x
```

当前执行分支示例：

```text
develop/v0.4.x
```

稳定起点：

```text
v0.3.6
```

当前收口状态：

```text
0.4.0 AI Write 全量范围冻结与分支治理：已完成
0.4.1 MCP 协议全量统一：已完成
0.4.2 Cloud MCP 直接写入全量能力：已完成
0.4.3 capture_parse 全量解析与会话持久化：已完成
```

v0.4 的核心判断：

```text
AI 写入必须真实、可确认、可审计、可撤销，并且 Cloud MCP / Local MCP / Flutter 入口的行为一致。
```

## 2. 版本目标

```text
Cloud MCP 与 Local MCP 共享 packages/protocol tool schema
Cloud MCP 具备完整真实写入能力
Local MCP 具备完整真实本地写入能力
capture_parse / capture_commit / capture_undo 形成完整闭环
AI 写入支持 memo / task / expense / asset ref 的核心路径
AI 写入和撤销全部进入 audit_logs
AI undo 进入 ai_trashed，不物理删除数据
Flutter 提供 AI 写入入口、候选确认入口和撤销入口
Cloud / Local MCP 建立 parity tests
提供 v0.4 AI 写入 smoke 脚本与 release gate
```

## 3. v0.4 明确不做

```text
不做复杂自然语言模型训练
不做自动读取系统通知 / 聊天记录 / 浏览器历史
不做 Android MCP Server
不做多人协作或共享写入
不做 AI 自动批量删除
不做未经确认的大规模导入
不做端到端加密
不做附件二进制上传体验扩展
不做 UI 大规模美化
```

v0.4 解决“AI 写入口完整可信”，不解决“AI 主动接管所有个人数据”。

## 4. 分支、tag 与提交规则

v0.4 每个修订号单独开分支：

```text
develop/v0.4.0
develop/v0.4.1
develop/v0.4.2
...
```

每轮流程：

```text
1. 从 develop/master 开 develop/v0.4.x
2. 完成当前修订号开发
3. 执行语法检查 / 测试 / smoke
4. commit
5. 合并回 develop/master
6. 在合并点打 tag v0.4.x
7. 删除当前 develop/v0.4.x 分支
8. 再开下一个 develop/v0.4.x+1
```

commit 信息格式：

```text
feat(模块): 中文说明
fix(模块): 中文说明
test(模块): 中文说明
```

### 0.4.3：capture_parse 全量解析与会话持久化

原因：AI-first 的核心不是单个结构化工具，而是把自然语言拆成多个候选动作，并让用户可确认、可选择、可追踪。

内容：

```text
capture_parse 支持 memo / task / expense / asset ref 候选动作
支持混合输入解析
支持 timezone / locale
持久化 capture session
记录原始文本、候选 actions、confidence、requires_confirmation
支持 session 过期
支持非法输入诊断
补齐解析规则测试
```

验收：

```text
capture_parse 返回稳定 capture_id
同一 capture_id 可被 capture_commit 查到
候选 actions 覆盖 memo_create / expense_create / task_create / asset_register_external_url
非法或过期 capture_id 有明确错误
capture_parse 本身不写入业务实体
解析测试覆盖混合输入最小场景
```

建议提交：

```text
feat(mcp): 实现v0.4.3捕获解析持久化
```

### 0.4.4：capture_commit 全量提交能力

验收：

```text
capture_commit 可提交全部 action
capture_commit 可只提交选择的 action
提交后返回 undo_token
created_entities 与实际写入实体一致
重复提交同一 capture_id 不产生重复数据
```

建议提交：

