# Lifly v0.2.x Local Data MVP 修订号开发计划

## 1. 版本命名规则

从 v0.2 开始，开发轮次不再使用 `dev` 后缀。每一轮都使用标准三段式版本号：

```text
0.2.0
0.2.1
0.2.2
...
```

规则：

```text
v0.2.x：Local Data MVP 版本族
x：本版本族内的修订号
每个修订号必须有明确范围、禁止事项和验证命令
只有通过完整 release gate 的修订号才允许打 tag
```

当前开发分支：

```text
feat/v0.2-local-data-mvp
```

v0.2 版本族完成后，合并回 `master`，在稳定合并点打最终 tag，例如：

```text
v0.2.8
```

最终 tag 以实际通过 release gate 的修订号为准。

## 2. 版本目标

v0.2.x 的目标是让 Lifly 具备真正的本地优先数据闭环：

```text
memo 可以离线创建、查看、编辑、删除，并在应用重启后不丢
task 可以离线创建、查看、完成、编辑、删除，并在应用重启后不丢
expense 可以离线创建、查看、搜索、统计，并在应用重启后不丢
所有本地写操作写入 audit_logs
所有本地记录维护 revision / created_at / updated_at / source
删除优先 soft delete，不物理删除
Flutter 页面可以在 Local Core 模式下读取本地数据
```

## 3. v0.2 明确不做

```text
不做 Cloud Sync
不做 PowerSync uploadData
不做跨端同步
不做复杂冲突解决
不做生产级账号体系
不做端到端加密
不做附件二进制完整上传
不做 Local MCP 到 Flutter 真实进程桥接
不做 UI 大规模美化
```

v0.2 只解决“本机数据能稳定写入、读取、重启后不丢”。

## 4. 修订号规划

### 0.2.0：版本规划与本地数据边界冻结

原因：v0.1.0 已完成工程基线，进入 v0.2 前必须先冻结本地数据版本边界，避免把云同步、AI 写入、附件等能力混入本地数据 MVP。

内容：

```text
建立 v0.2.x 开发计划文档
明确每个 0.2.x 修订号的范围
同步版本控制规则：不使用 dev 后缀
确认 v0.2 只做 Local Data MVP
确认当前分支为 feat/v0.2-local-data-mvp
```

验收：

```text
docs/development-plans/v0.2.0-local-data-mvp.md 入仓
docs/59-version-control-plan.md 同步标准修订号规则
docs/development-plans/README.md 指向当前 v0.2 计划
```

建议提交：

```text
fix(docs): 规划v0.2.0本地数据修订号
```

### 0.2.1：PowerSync Local Core 基础底座

原因：本地数据闭环不能直接从页面开始，必须先有稳定的数据库初始化、schema 入口和 health 诊断。

内容：

```text
检查 apps/client_flutter/lib/data/powersync 当前结构
实现或收口 PowerSyncDatabase 初始化入口
实现 Dart PowerSyncLocalCoreBridge health
统一 LocalCoreContext / timestamp / id 生成工具
保留 FakeLocalCoreBridge 用于测试和回退
settings 中可以显示本地数据层 health
```

验收：

```text
Local Core health 返回 powersync 或明确 fake/fallback 状态
Flutter analyze 通过
Flutter test 通过
本地数据初始化失败时有可诊断错误，不让页面静默失败
```

建议提交：

```text
feat(local-core): 建立v0.2.1本地数据底座
```

### 0.2.2：audit_logs 与本地写入公共工具

原因：v0.2 后续所有 memo / task / expense 写入都要统一维护审计日志、revision、source 和更新时间；如果每个模块各写一套，后续同步会很难收口。

内容：

```text
实现本地 audit_logs writer
统一 revision 自增策略
统一 created_at / updated_at 写入策略
统一 source / actor / tool_name 记录
定义本地写入事务边界
为后续 undo / sync 预留必要字段
```

验收：

```text
任意本地写入可生成 audit log
audit log 与实体 id 可关联
重复写入不会破坏 revision
Flutter test 覆盖 audit writer 主路径
```

建议提交：

```text
feat(local-core): 增加v0.2.2本地审计日志
```

### 0.2.3：memo 本地 CRUD 闭环

原因：memo 是 Lifly 的最低成本记录入口，应该先完成本地 create/search/update/delete，作为后续 task 和 expense 的模式样板。

内容：

```text
实现 memo 本地 create
实现 memo 本地 search/list
实现 memo 本地 update
实现 memo 本地 soft delete
写入 audit_logs
维护 revision / updated_at / status
补充 memo 本地持久化测试
```

验收：

```text
断网可创建 memo
应用重启后 memo 不丢
memo search 可以查到本地创建的数据
memo update 后 revision 增加
memo delete 后 status 变更，不物理删除
```

建议提交：

```text
feat(memo): 实现v0.2.3本地备忘闭环
```

### 0.2.4：task 本地 CRUD / complete 闭环

原因：task 是本地生活管理的第二条主路径，需要在本地完成创建、查看、完成和软删除，确保提醒类数据不依赖网络。

内容：

```text
实现 task 本地 create
实现 task 本地 list/filter
实现 task 本地 update
实现 task complete
实现 task soft delete
写入 audit_logs
维护 task_status / completed_at / revision
补充 task 本地持久化测试
```

验收：

```text
断网可创建 task
应用重启后 task 不丢
task complete 后状态持久化
task list 可以按 todo / done 过滤
所有写操作都有 audit log
```

建议提交：

```text
feat(task): 实现v0.2.4本地任务闭环
```

### 0.2.5：expense 本地 create/search/summary 闭环

原因：记账数据需要本地可写、可查、可统计，才能支撑 v0.2 的 Local Data MVP。

内容：

```text
实现 expense 本地 create
实现 expense 本地 search/list
实现 expense 本地 summary
实现 expense soft delete
写入 audit_logs
```


建议提交：

```text

```

### 0.2.6：Flutter 页面切换到 Local Core 模式

原因：数据层闭环完成后，页面必须真正读取本地数据，否则 v0.2 只是底层能力，不是可用 MVP。

内容：

```text
memo 页面接入 Local Core repository
task 页面接入 Local Core repository
ledger 页面接入 Local Core repository
settings 展示当前数据模式
保留 API 模式或 fake 模式的明确边界
本地写入错误在页面可见
```

验收：

```text
Flutter 页面可以展示本地 memo / task / expense
页面新增数据后列表刷新
详情页读取本地数据
错误状态不会造成页面崩溃
Flutter widget test 覆盖主入口
```

建议提交：

```text
feat(flutter): 接入v0.2.6本地数据模式
```

### 0.2.7：本地持久化回归与重启验证

原因：v0.2 的关键不是“能写一次”，而是“重启后不丢”。必须有专门回归测试覆盖数据库重开、查询和状态保持。

内容：

```text
覆盖 revision 与 audit_logs 重启后保留
记录本地持久化回归验证方式
```

验收：

```text
本地数据库关闭再打开后数据仍存在
memo / task / expense 主路径均有重启回归测试
soft delete / revision / audit_logs 重启后保留
Flutter analyze 通过
Flutter test 通过
持久化验证方式已记录到 docs/62-local-core-persistence-regression.md
```

建议提交：


## 6. v0.2 Definition of Done

v0.2.x 完成时必须同时满足：

```text
1. memo / task / expense 可以离线写入
2. 应用重启后 memo / task / expense 不丢
3. memo / task / expense 页面可以读取本地数据
4. task complete 状态可以持久化
5. expense summary 可以基于本地数据统计
6. 删除采用 soft delete，不物理删除
7. 所有本地写入都有 audit_logs
8. revision / updated_at / source 维护一致
9. Flutter analyze/test 通过
10. pnpm test/typecheck 通过
11. Local MCP smoke 不被破坏
12. 不包含 Cloud Sync / uploadData / 跨端同步能力
```
