# 23. 开源与商业化策略

## 1. 当前方向

Lifily 初期为个人自用工具，后续可能商业化。架构按“核心开源 + 官方云服务商业化”的方向设计。

## 2. 可开源部分

建议开源：

- 客户端；
- MCP tool schema；
- 本地 MCP；
- 核心领域模型；
- 基础后端，视策略；
- 文档；
- 导入导出格式。

## 3. 可商业化部分

可商业化：

- 官方云同步；
- 大容量附件存储；
- 官方 AI 模型额度；
- 高级导入导出；
- 第三方同步；
- 高级搜索；
- 备份恢复；
- 多端高级能力。

## 4. 许可证选择

候选：

### 4.1 AGPL

优点：

- 防止别人拿去直接闭源做 SaaS；
- 保护开源项目。

缺点：

- 商业合作门槛较高；
- 企业采用可能谨慎。

### 4.2 Apache/MIT + 商业云

优点：

- 生态友好；
- 更容易被开发者采用。

缺点：

- 被别人商业化复制的风险更高。

### 4.3 双许可证

优点：

- 开源和商业兼顾。

缺点：

- 管理复杂。

## 5. 建议

如果目标是形成开发者生态：

```text
客户端 + MCP + 协议 + 本地模式开源
官方云服务商业化
```

许可证可先暂定，代码早期不急于完全公开。

## 6. 数据可迁移承诺

商业化也必须坚持：

- 用户可以导出数据；
- 用户可以删除云端数据；
- 用户可以本地使用核心功能；
- 不以数据锁定作为商业模式。

## 7. 插件生态

后续可以开放：

- 导入插件；
- 导出插件；
- MCP 工具插件；
- 分类规则插件；
- 第三方同步插件。

## 8. 商业化风险

需要注意：

- 云存储成本；
- AI 调用成本；
- 同步服务成本；
- 隐私合规；
- 用户数据删除义务；
- 付费功能边界。
