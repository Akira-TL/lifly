# 00. 已确认决策记录

## 1. 产品定位

当前阶段是个人自用工具，后续可能演进为商业产品。架构上按可开源、可私有部署、可商业化云服务的方式设计。

## 2. 产品入口

第一版同时支持：

- App 内手动记录；
- App 内 AI 输入；
- 外部 MCP Client 调用；
- 后续机器人通过 MCP 调用。

App 打开后的手动记录是基础能力，但产品核心体验是“用户自然语言输入，系统自动拆解为备忘录、记账、任务提醒等结构化生活数据”。

## 3. 平台范围

MVP 优先平台：

- Windows；
- Android。

架构预留：

- macOS；
- iOS；
- Linux；
- Web。

## 4. 客户端框架

优先采用 Flutter。选择理由：

- 支持 Windows + Android 的第一阶段目标；
- 未来可扩展到 macOS/iOS/Linux/Web；
- 不是 Chromium 套壳；
- UI 一致性较好。

## 5. 同步策略

采用 PowerSync，避免后期从自研同步迁移到成熟同步系统的成本。

原则：

- 本地 SQLite 是客户端主要读写数据库；
- 云端 PostgreSQL 是权威云端数据库；
- 通过 PowerSync 实现离线写入、恢复联网后同步；
- 附件二进制不走 PowerSync，只同步附件元数据。

## 6. 加密策略

MVP 不做端到端加密。需要做到：

- 本地数据可正常离线使用；
- 云端权限隔离；
- token 可吊销；
- 附件私有访问；
- 后续可演进到更强加密策略。

## 7. MCP 策略

- 云端 MCP 是默认能力；
- App 内 AI 默认走云端 MCP；
- 外部机器人默认走云端 MCP；
- OpenClaw/Hermes 在线场景走云端 MCP；
- Windows 桌面端支持本地 MCP，用于本地模型、离线 AI、私有部署；
- Android 不做 MCP Server。

## 8. AI 写入策略

AI 不直接写数据库，所有写入都通过 MCP/API。所有写入、修改、删除都必须产生审计日志。

AI 删除不真删，进入 AI 回收站。用户确认删除后才进入普通删除流程。

## 9. MVP 模块

第一版只做：

- 备忘录；
- 记账；
- 任务提醒。

底层预留 calendar_events，第一版不做完整日历 UI。

## 10. 记账范围

MVP 支持：

- 自然语言记账；
- 手动记账；
- 通用 CSV 导入；
- 支付宝账单 CSV 导入；
- 微信账单 CSV 导入；
- 导入预览；
- 批次回滚；
- 重复检测。

暂不做 Android 通知监听，原因：

- 保护用户隐私；
- 降低系统负载；
- 降低 Android 端复杂度。

## 11. 附件系统

备忘录不是纯文本，而是 Markdown + 附件引用。附件包括：

- 图片；
- PDF；
- PPT/PPTX；
- 思维导图；
- 普通文件；
- 外部链接；
- 后续第三方文档引用。

文件存储策略：

- 内部附件：对象存储，数据库记录 asset_id/storage_key；
- 外部附件：数据库记录 external_url；
- 本地可缓存；
- 修改后同步。

## 12. 第三方同步

MVP 只预留 external_source 等字段，不做飞书、Notion、Obsidian 双向同步。

后续优先级：

1. 导入；
2. 导出；
3. 单向同步；
4. 双向同步。

## 13. 开源策略

倾向 C + D：

- 核心开源；
- 官方云服务商业化；
- 许可证后续再最终确定，可考虑 AGPL 或核心开源 + 商业云服务。
