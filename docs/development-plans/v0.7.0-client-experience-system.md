# Lifly v0.7.x 客户端 UI/交互体验统一全量开发计划

## 1. 版本定位

v0.6 已经把导入导出体验层做成闭环：

```text
导入：选择文件 -> 上传预览 -> 完整预览 -> 提交 -> 批次追踪
导出：选择范围 -> 元数据预览 -> 下载导出流
门禁：Cloud API / Local Core 边界、测试、手动验收文档
```

v0.7.x 不再优先扩数据能力，而是集中解决 Flutter 客户端当前页面密度、导航层级、空状态、错误态、桌面端可用性和视觉一致性问题，让已有功能真正适合日常使用。

## 2. 平台范围

```text
主要平台：Flutter 客户端 apps/client_flutter
重点形态：Linux 桌面端、Web，其次兼顾手机端响应式
配套平台：服务端 services/api，仅在 UI 诊断需要时补少量只读辅助信息
暂不处理：小程序
```

## 3. 总目标

```text
统一应用级导航结构
统一页面标题、说明、操作区和状态区
统一卡片、列表、表单、筛选、空状态、错误态
降低设置页和数据管理页的信息噪音
提升桌面端宽屏布局可用性
提升导入导出链路的视觉层级和可读性
补齐关键页面 widget regression tests
输出手动验收清单
```

## 4. v0.7 明确不做

```text
不做全新设计系统重写
不做复杂主题编辑器
不做多主题/皮肤市场
不做移动端原生平台深度适配
不做小程序端
不做服务端大接口重构
不做复杂动效系统
不做图表分析大盘
```

## 5. 设计原则

```text
先结构，后装饰
先桌面/Web 信息密度，再兼容手机端
每个页面必须有清晰标题、说明、主操作和错误恢复
设置页只保留入口和诊断摘要，深层能力进入子页面
列表页优先解决空状态、加载状态、错误状态和分页状态
导入导出页面优先保证用户知道当前处于 Cloud API 还是 Local Core
```

## 6. 修订号规划

### 0.7.0：客户端体验系统范围冻结

原因：v0.7 会跨首页、备忘、搜索、AI、记账、任务、设置和导入导出页面，必须先冻结体验原则、页面分层和验收标准，避免边改边散。

内容：

```text
确认 v0.7 平台范围
确认导航、页面结构、状态组件、表单和列表的统一目标
确认桌面/Web 优先级
确认 v0.7 不做项
更新开发计划文档
```

提交：

```text
feat(docs): 规划v0.7.0客户端体验系统开发
```

### 0.7.1：应用 Shell 与导航体验重构

原因：当前底部导航承载 7 个入口，在桌面/Web 上信息密度和可扩展性都不理想。应先建立响应式 shell，后续页面优化才有统一容器。

内容：

```text
抽象 AppShell 导航模型
桌面/Web 使用 NavigationRail 或侧边导航
窄屏保留 NavigationBar
统一页面容器宽度和 padding
保留 IndexedStack 状态
补齐 shell widget tests
```

提交：

```text
feat(client): 实现v0.7.1响应式导航框架
```

### 0.7.2：首页与全局状态组件收口

原因：首页是进入应用后的认知入口，需要先统一全局页面标题、状态卡片、空状态、错误态组件，再下沉到各功能页复用。

内容：

```text
新增共享 PageScaffold / SectionCard / EmptyState / ErrorState 组件
首页改用统一组件
首页展示数据模式、同步状态、最近活动摘要
错误态提供重试动作
补齐 widget tests
```

提交：

```text
feat(client): 实现v0.7.2首页与状态组件收口
```

### 0.7.3：备忘与任务列表体验优化

内容：

```text

任务列表统一标题、筛选、空状态和错误态
桌面宽屏下优化列表最大宽度
移动窄屏保持单列体验
补齐 widget tests
```

```text

```

### 0.7.4：记账页面与导入结果体验优化

原因：记账页和导入提交结果强相关。导入提交后用户需要更清晰地理解流水是否进入账本，以及如何检查结果。

```text

导入提交结果增加跳转/刷新提示
导入批次详情和记账列表之间建立更清晰的用户路径
统一金额、方向、时间显示格式
补齐 widget tests
```

内容：

```text

API / AI / Local Core / PowerSync 诊断进入独立页面
数据管理继续保持独立分组
关于信息收口
settings_page.dart 降低行数和职责
补齐 widget tests
```

提交：

```text

```

## 7. 验收门槛

每个修订号至少满足：

```text
flutter analyze 通过
相关 widget tests 通过
git diff --check 无输出
新增/修改文件行数符合限制
用户可手动打开对应 UI 路径验证
```

v0.7 最终发布前必须满足：

```text

Linux 桌面端主要路径可用
Web 主要路径可用，若当前环境没有 chrome，则记录为用户手动验收项
Cloud API / Local Core 边界提示正确
设置页、首页、导入导出、记账、备忘、任务、搜索、AI 页面无明显割裂
```
