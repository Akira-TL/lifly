# 61. Lifly v0.1.0 全量开发内容规划

## 1. 文档目的

本文档用于把 `docs/60-major-version-roadmap.md` 中的 `v0.1.0 Foundation Baseline` 拆成可执行的全量开发内容、验收标准和提交切片。

本文档中的 `v0.1.0` 指第一个工程基线版本，不指完整个人生产可用版本。真实本地持久化、跨端云同步、AI 真实本地写入、附件完整体验和导入导出完整 UI 均顺延到后续大版本。

## 2. 版本定位

```text
版本号：v0.1.0-dev -> v0.1.0
版本名称：Foundation Baseline
版本目标：让 Lifly 具备稳定、可测试、可继续由 AI agent 迭代的工程基线
核心原则：冻结边界、统一命名、稳定协议、稳定测试、稳定文档
下一版本入口：v0.2.0 Local Data MVP
```

`v0.1.0` 成功的标准不是“产品已经完整可用”，而是：

```text
后续开发者/AI agent 能基于同一套目录、协议、文档、测试和版本规则继续推进 v0.2.0。
```

## 4. v0.1.0 范围总览

### 4.1 必须完成

```text
1. 项目命名统一为 Lifly / lifly
2. pnpm workspace 与 lockfile 稳定，pnpm-lock.yaml 入仓
3. Flutter client、FastAPI backend、packages/protocol、packages/local-core、apps/local-mcp 的边界清楚
4. FastAPI health/version 统一为 0.1.0
5. MCP v0.1 tool schema 冻结
6. Cloud MCP contract / smoke 测试通过
7. Local MCP stdio skeleton 存在并可 smoke
8. TypeScript Local Core fake bridge 存在并可测试
9. Flutter Dart Local Core fake bridge 存在并可测试
10. Flutter 首页/备忘/记账/任务/设置基础页面可运行
11. Flutter 基础 API 数据接入、列表组件、详情编辑删除、分页过滤等当前基线收口
12. docs 中版本控制、路线图、release checklist、agent 协作规则完整
13. 基础检查命令可被开发者重复执行
```

### 4.2 明确不做

```text
1. 不做真实本地持久化
2. 不做 PowerSync uploadData
3. 不做 Windows / Android 跨端云同步
4. 不做生产级 auth / 多用户权限
5. 不做 Local MCP 到 Flutter/Dart 真实数据层调用
6. 不做附件完整上传体验
7. 不做 CSV 导入导出完整 UI
8. 不做复杂冲突解决
9. 不做端到端加密
10. 不做正式安装包和公开发布
```

### 5.8 Testing / CI / Release Gate

目标：让 v0.1.0 可以被重复验证，而不是只靠人工判断。

交付内容：

```text
pnpm test
pnpm typecheck
Flutter analyze/test
FastAPI MCP contract test
Cloud MCP smoke script
Local MCP smoke script
git diff --check
基础 CI 或本地等价脚本
release checklist
```

v0.1.0 release gate：

```bash
pnpm test
pnpm typecheck
cd apps/client_flutter && flutter analyze
cd apps/client_flutter && flutter test
cd services/api && uv run --group dev pytest tests/integration/test_mcp_v0_1_contract.py
bash scripts/smoke-mcp-v0.1.sh
bash scripts/smoke-local-mcp-v0.1.sh
git diff --check
```

允许说明但不阻塞的项目：

```text
Android / Windows / Linux 构建因本机环境不完整失败时，可以记录为环境问题，不作为 v0.1.0 阻塞项。
但 Flutter analyze/test 仍应作为代码质量 gate。
```

## 7. 推荐提交顺序

```text
1. fix(docs): 规划v0.1全量开发内容
2. fix(project): 统一lifly命名和版本号
3. fix(workspace): 稳定pnpm依赖和脚本
4. fix(mcp): 冻结v0.1工具协议
5. fix(api): 收口v0.1后端基线
6. fix(local-core): 收口本地核心fake基线
7. fix(flutter): 收口v0.1客户端基线
8. fix(release): 完成v0.1发布门禁
```

其中第 1 个提交仅为规划提交；后续提交按模块修复，不应把大批无关文件混在同一个 commit 中。

## 8. 分支建议

当前 v0.1 收口阶段建议使用：

```text
agent/v0.1-release-gate
```

如果继续沿用当前 agent 分支，也应保持以下规则：

```text
每个提交只覆盖一个模块
提交前运行对应最小检查
最终合入 master 前运行完整 release gate
正式 v0.1.0 之前可以使用 v0.1.0-rc.1 tag
```

正式发布路径：

```text
agent/v0.1-release-gate
  -> PR
  -> master
  -> release/v0.1.0
  -> v0.1.0-rc.1
  -> v0.1.0
```

## 9. v0.1.0 Definition of Done

`v0.1.0` 必须同时满足：

```text
1. 命名和版本统一
2. 根 workspace 依赖稳定
3. 后端 API/MCP 基础路径可验证
4. MCP v0.1 schema 冻结
5. Local MCP/Local Core fake 链路可验证
6. Flutter 基础页面和状态边界可验证
7. 文档索引、路线图、版本控制、release gate 完整
8. 所有必须检查命令通过，或有明确环境例外说明
9. 没有把 v0.2+ 功能提前塞进 v0.1 release gate
```

## 10. v0.1.0 之后立即进入 v0.2.0

v0.1.0 发布后，不建议继续扩展 Foundation 功能。下一步直接进入：

```text
v0.2.0 Local Data MVP
```

优先开发顺序沿用 `docs/60-major-version-roadmap.md`：

```text
1. LC-0201 Implement Dart PowerSyncLocalCoreBridge health and shared utilities
2. LC-0202 Implement local audit log writer
3. LC-0203 Implement local memo create/search/update/delete
4. LC-0204 Implement local task create/list/complete/update/delete
5. LC-0205 Implement local expense create/search/summary
6. LC-0206 Switch Flutter memo/task/ledger pages to Local Core mode
7. LC-0207 Add local persistence regression tests
```

判断标准：

```text
只要 memo / task / expense 可以离线写入并重启不丢，v0.2.0 的核心就成立。
```
