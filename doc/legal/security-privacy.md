# 认证、安全与隐私

## 1. 安全目标

MVP 不做端到端加密，但必须保证基础安全：

- 用户数据隔离；
- 私有附件不可公开访问；
- Token 可吊销；
- MCP 调用可审计；
- 外部机器人使用独立 token；
- 用户可导出和删除数据。

## 2. 账号模式

```text
本地模式：免登录
云同步模式：必须登录
云端 MCP：必须认证
本地 MCP：本机授权
```

## 3. Token 类型

建议：

```text
access_token
refresh_token
mcp_api_token
bot_token
local_mcp_token
```

外部机器人不要复用主账号密码，应使用可吊销 token。

## 4. 权限模型

MVP 不做多用户/工作区，但所有表仍必须有 user_id。

原因：

- 未来商业化；
- 云端隔离；
- 防止越权；
- 方便迁移到 workspace。

## 5. 附件安全

内部附件：

- 对象存储私有；
- 客户端通过后端获取短期访问链接；
- 不直接暴露 storage_key；
- 上传完成后校验文件大小和类型。

外部附件：

- 仅保存 URL；
- UI 标记可能失效；
- 用户可转存为内部附件。

## 6. 隐私策略

明确不做 Android 通知监听，原因：

- 避免采集支付通知；
- 降低隐私风险；
- 降低系统常驻负载；
- 用户通过 CSV 导入或手动记账即可。

## 7. MCP 安全

Cloud MCP：

- 使用 token；
- 每次调用记录 request_id；
- 写操作记录 audit log；
- 高风险操作要求确认。

Local MCP：

- 仅访问本机当前用户；
- 不默认暴露网络端口；
- 优先 stdio；
- 私有部署时由用户自行配置。

## 8. 数据删除

用户删除需要真实可删除内容：

- 先进入 user_trashed；
- 30 天内可恢复；
- 30 天后 purged；
- 清除正文、金额、备注、附件引用等敏感内容；
- 保留 tombstone 用于同步一致性。

## 9. 日志安全

日志不得记录：

- 完整 access token；
- 完整 API key；
- 敏感附件内容；
- 大段用户隐私正文。

调试环境也要遵守。
